## 7. Feature engineering and selection

- **Team decision: model on all columns.** Every original column is kept so no potentially useful signal is lost. The primary set `all_no_port` has **79 features** (all 77 original columns except Destination Port, plus 2 sentinel flags); `all_with_port` adds Destination Port and `is_well_known_port` (**81**).
- **Reduced comparison set:** `reduced_no_port` (**43 features**) drops 10 constant columns, 8 exact copies and 18 features with |r| > 0.95 to a stronger kept feature (ranked by train AUC, fit on the stratified training split only). It exists only to test whether pruning loses information.
- **Created:** `init_win_fwd_missing`, `init_win_bwd_missing` (sentinel flags), `is_well_known_port` (port < 1024), target `is_scan`.
- **Transformation:** signed log1p (handles -1 sentinel) → StandardScaler, inside an sklearn Pipeline fit on train only (logistic regression only; trees use raw values). Constant columns become 0 after scaling and receive zero weight.
- **Encoding:** no categorical features besides the label. Destination Port is kept numeric and used only in the with-port leakage check.

**All features vs reduced set.** With all columns, logistic regression makes 6 false alarms (FPR 0.03%) versus 17 (FPR 0.09%) with the reduced set, at the same recall (0.9982 vs 0.9982). Several columns the reduced set drops carry large weights in the all-features model, e.g. Total Backward Packets (rank 7 of 79); Subflow Bwd Packets (rank 8 of 79); Flow IAT Std (rank 10 of 79). On Monday the two sets are close (0.13% vs 0.12%), as on the time-ordered split (1 vs 0 false alarms). Keeping all columns never costs recall and lowers validation false alarms, so the all-features set is the primary set.

**Interpretation.** The majority-class baseline catches no scans (recall 0), which shows why accuracy (57.5%) is misleading here. The three-condition rule already reaches recall 0.984 with 3.49% false positives on validation, but flags 5.05% on the time-ordered split and 5.84% of Monday's benign traffic, so it **fails the 5% false-alarm target** on new traffic. Logistic regression on all features (no port) reaches precision 0.9996, recall 0.9982 and FPR 0.03% (24 missed scans, 6 false alarms out of 32,040 flows), and flags only 0.13% of Monday flows. Adding Destination Port changes FPR only from 0.03% to 0.02%, so the model is **not** relying on port memorisation. Scores this high are expected: the scans are one-packet SYN probes from Nmap, which look nothing like normal traffic. The real risks are that the model learns this lab's tool fingerprint (e.g. 1024-byte TCP window) and that the random split is optimistic, so cross-day and other-scanner testing matter more than squeezing out extra accuracy.

## 10. Surprises and changes from the proposal

1. **Scans are the majority in the raw file (55.5%)**, not the minority as the proposal assumed. After dedup the split is 57.5% / 42.5% (BENIGN / PortScan).
2. **42.9% of scan rows are exact duplicates** (vs 3.3% of benign rows). Dedup is essential to avoid inflated scores.
3. **8 columns are exact copies of others**, including SYN Flag Count = Fwd PSH Flags (a known CICFlowMeter bug). They are flagged but kept, together with the constant columns, because the team chose to model on all columns.
3b. **Keeping all columns helps:** false alarms fall from 17 (reduced set) to 6 (all features) at equal recall.
4. **Baselines already exceed the success criteria** (recall ≥ 0.90, FPR ≤ 5%) on validation, so the rest of the project shifts toward robustness and explanation rather than raw accuracy.
5. **Destination Port is not driving the results** (with/without port nearly identical). However, the TCP window value 1024 marks raw SYN probes)% of scan flows, a scanner fingerprint the model can exploit.
6. **The simple rule fails on another day's traffic** (Monday FPR above 5%), which shows why outside-day testing was added to the plan.
7. **Split strategy extended:** the proposal had only a stratified 70/15/15 split. A time-ordered split and a Monday false-positive check were added.

## 11. Open issues and next steps (before the Status Report)

- Train Random Forest and XGBoost on `all_no_port` (with `reduced_no_port` as a comparison); compare against these baselines on the same validation set; then tune with stratified 5-fold CV on train.
- **Known-tester allowlist** (`src/allowlist.py`, `config/known_scanners.csv`, tested in `tests/test_allowlist.py`): evaluate on the GeneratedLabelledFlows release, which has Source IP and Timestamp.
- **Slow-scan features** (`src/slow_scan.py`, tested in `tests/test_slow_scan.py`): per-source distinct ports/hosts and failed-connection ratio over 5 min / 1 h / 24 h windows; evaluate on the same release.
- **Robustness tests:** (a) remove the TCP-window features to check dependence on the Nmap fingerprint; (b) group-aware split (by scan burst) instead of random rows; (c) add benign traffic from other days (Tuesday–Thursday) as extra false-positive tests.
- Threshold tuning: pick the operating point on validation for recall ≥ 0.90 at the lowest FPR, then report once on the locked test set.
- Explainability: permutation importance or SHAP for the tree models; this feeds the dashboard's 'why was this flagged' panel.
- Dashboard prototype (Streamlit): ranked list of flagged flows with top contributing features.
- Limitations to state in the final report: 2017 lab data, a single scanner tool, no slow-scan examples, no timestamps.
