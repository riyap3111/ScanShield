# ScanShield: Detecting Network Port Scanning Using Flow-Level Traffic Analysis

**Team NetSentries** · Riya Sanjiv Pradhan & Ojas Prashant Suratkar · Cybersecurity Analytics (IDS track)

ScanShield classifies network flows from the CICIDS2017 dataset as **BENIGN** or **PortScan**. It is a detection model, not a live monitoring or blocking system. The main metrics are **recall on scans (target ≥ 0.90)** and **false-positive rate on benign traffic (target ≤ 5%)**.

The models use **all original columns**. A reduced, de-correlated set is kept only as a comparison. On validation it nearly triples the false alarms (6 → 17); on Monday's traffic and on the time-ordered split the two sets perform about the same.

### Deployment controls from the risk review
- **Known-tester allowlist** (`src/allowlist.py`, `config/known_scanners.csv`): suppresses alerts from registered internal scanners (e.g. Nessus, Nmap inventory) only for their approved source, ports and time window, and keeps suppressed alerts for audit.
- **Slow-scan features** (`src/slow_scan.py`): counts distinct ports and hosts per source, plus the failed-connection ratio, over 5 min, 1 h and 24 h windows to catch scans paced over hours.
- Both need Source IP and Timestamp, which this CSV release lacks. They are unit-tested (`python tests/test_allowlist.py`, `python tests/test_slow_scan.py`) and will be evaluated on CIC's GeneratedLabelledFlows release.

## Reproduce

```bash
python -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements.txt
# put the two CICIDS2017 CSVs in data/raw/ (see data/README.md), then:
python data/prepare_raw.py                               # compresses + checks SHA256
bash run_all.sh                                          # Windows without bash: run src/01…06 in order
```

All randomness uses `random_state = 42`. The scripts check the raw file against hand-verified facts (row count, label counts, duplicate count) and stop if anything differs.

## Pipeline

1. **01_load_and_audit**: builds the data dictionary and measures missing, infinite and negative values, constant and duplicate columns, duplicate rows, conflicting labels, outliers and class balance. It does not change any data.
2. **02_clean**: strips column names; drops inf/NaN and impossible negative rows; flags the `-1` TCP-window sentinel; flags (keeps) 10 constant and 8 duplicate columns; de-duplicates rows **before** splitting; checks for conflicting labels; encodes the target. Each step is logged.
3. **03_eda**: class balance, feature distributions by class, univariate separability (AUC), correlation, port and time patterns.
4. **04_features_and_split**: engineered features; feature sets `all_no_port` (primary, 79), `all_with_port` (81) and `reduced_no_port` (43; de-correlation **fit on train only**, comparison only); stratified 70/15/15 split plus a time-ordered split.
5. **05_baselines**: majority class, threshold rule, logistic regression (all features, all + port, reduced) and a depth-4 tree. Scored on validation and on an outside day (Monday, all benign); also checks which excluded columns carry weight.
6. **06_write_summary**: writes `RESULTS_SUMMARY.md` from the saved outputs.
