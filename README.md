# ScanShield: Detecting Network Port Scanning Using Flow-Level Traffic Analysis

**Team NetSentries** · Riya Sanjiv Pradhan & Ojas Prashant Suratkar · Cybersecurity Analytics (IDS track)

ScanShield classifies network flows from the CICIDS2017 dataset as **BENIGN** or **PortScan**. It is a detection model, not a live monitoring or blocking system. The main metrics are **recall on scans (target ≥ 0.90)** and **false-positive rate on benign traffic (target ≤ 5%)**.

### Deployment controls from the risk review
- **Known-tester allowlist** (`src/allowlist.py`, `config/known_scanners.csv`): suppresses alerts from registered internal scanners (e.g. Nessus, Nmap inventory) only for their approved source, ports and time window, and keeps suppressed alerts for audit.
- **Slow-scan features** (`src/slow_scan.py`): counts distinct ports and hosts per source, plus the failed-connection ratio, over 5 min, 1 h and 24 h windows to catch scans paced over hours.
- Both need Source IP and Timestamp, which this CSV release lacks. They are unit-tested (`python tests/test_allowlist.py`, `python tests/test_slow_scan.py`) and will be evaluated on CIC's GeneratedLabelledFlows release.

## Reproduce

```bash
python -m venv .venv && source .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements.txt
# put the two CICIDS2017 CSVs in data/raw/ (see data/README.md), then:
python data/prepare_raw.py                               # compresses + checks SHA256
bash run_all.sh                                          # Windows without bash: run src/01…14 in order
python reports/build_deliverable3.py                     # rebuilds the Status Report .docx
```

All randomness uses `random_state = 42`. The scripts check the raw file against hand-verified facts (row count, label counts, duplicate count) and stop if anything differs. Steps 10 and 13 additionally need the other CICIDS2017 day files in `~/Desktop/CICIDS_dataset` (see [`data/README.md`](data/README.md)); without them those two steps skip themselves and the rest of the pipeline still runs.

The hyperparameter search in step 08 is the slow part — budget roughly an hour on a laptop. Everything else runs in a few minutes.

## Pipeline

1. **01_load_and_audit**: builds the data dictionary and measures missing, infinite and negative values, constant and duplicate columns, duplicate rows, conflicting labels, outliers and class balance. It does not change any data.
2. **02_clean**: strips column names; drops inf/NaN and impossible negative rows; flags the `-1` TCP-window sentinel; flags (keeps) 10 constant and 8 duplicate columns; de-duplicates rows **before** splitting; checks for conflicting labels; encodes the target. Each step is logged.
3. **03_eda**: class balance, feature distributions by class, univariate separability (AUC), correlation, port and time patterns.
4. **04_features_and_split**: engineered features; feature sets `all_no_port` (primary, 79), `all_with_port` (81) and `reduced_no_port` (43; de-correlation **fit on train only**, comparison only); stratified 70/15/15 split plus a time-ordered split.
5. **05_baselines**: majority class, threshold rule, logistic regression (all features, all + port, reduced) and a depth-4 tree. Scored on validation and on an outside day (Monday, all benign); also checks which excluded columns carry weight.
6. **06_write_summary**: writes `RESULTS_SUMMARY.md` from the saved outputs.

### Deliverable 3 (Interim Status Report)

7. **07_feature_engineering**: keeps every original column and adds 28 engineered features (payload per packet, reply ratio, flag density, header-to-payload ratio, port class, burstiness). Builds the primary `full` set plus two diagnostic ablations, `original_only` and `no_fingerprint`.
8. **08_train_models**: logistic regression, Random Forest and histogram gradient boosting. Each gets a 15-candidate randomised search with 5-fold stratified CV on the training split, scored by PR-AUC. The alert threshold is chosen on validation (highest F1 within the 5% FPR ceiling), frozen, and only then is the test split scored — once. Also runs the feature-set ablation and a three-seed stability check.
9. **09_evaluate**: comparison curves, confusion matrices and a structured error analysis (representative cases, grouped causes, port breakdown).
10. **10_generalization**: schema-compatibility audit and scoring on all seven other CICIDS2017 day files — 2.5 M flows and twelve unseen attack types.
11. **11_adversarial**: five evasion attacks (timing, payload padding, TCP-window reshaping, handshake mimicry, combined) and an adversarial-training defense.
12. **12_responsible_ai**: unequal-performance review across service group, flow size, capture period and capture day; permutation importance and SHAP; privacy and governance table.
13. **13_monitoring**: PSI drift baselines, alert-volume baselines, monitoring plan, response workflow and alert logging schema.
14. **14_write_summary_d3**: writes `RESULTS_DELIVERABLE3.md` from the saved outputs.

The Status Report itself is built from those same outputs by `python reports/build_deliverable3.py`, so no number in the document is typed by hand.
